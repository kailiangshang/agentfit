# AgentFit 高风险动作与人工门禁清单

> 状态:设计契约 `READY`,真实运行 `NOT_STARTED`。高风险动作必须保留人工确认、审批、回滚和审计边界。

## 事实源

本清单从以下文件派生:

- [AgentFit 整体方案](../../../docs/agentfit-solution.md) §8.4(安全和 Human 边界)、§9(评测与审计);
- [AgentTeams 落地设计](../design/agentteams-landing-design.md) §7(错误与降级);
- 官方要求矩阵 §2(高风险动作)、§3(八步闭环第 7 步审批与回滚)。

## 核心原则

1. **Human 不是兜底文案**,而是候选图中的能力与约束对象。每个门禁必须有触发条件、审批主体、输入输出、响应时限、拒绝和回滚记录;
2. **高风险动作执行前必须获得明确批准**,无批准即拒绝执行并保留 Trace;
3. **成功与失败证据同等保留**;
4. **密钥由基础设施持有,不进入 Agent 上下文**;
5. **沙箱、超时、预算和最大循环次数**必须预先设定;
6. **失败、拒绝、人工接管、降级和回滚路径**必须预先定义。

## 人工门禁类型

| 门禁类型 | 触发时机 | 审批主体 | 拒绝路径 | 回滚路径 |
|---|---|---|---|---|
| 任务冻结门禁 | 任务说明书产出后,候选生成前 | 责任业务方 | 缩小范围 / 补充材料 / 拒绝自动化 | 任务版本回退 |
| 试验批准门禁 | 候选生成后,统一试验前 | 责任业务方 + 审计官 | 拒绝试验范围 / 缩小预算 | 候选版本回退 |
| 预算变更门禁 | 任何预算提升请求 | 责任业务方 | 维持原预算并停止扩展 | 不适用(只升不降需审批) |
| 真实发布门禁 | 候选产生外部写入或发布动作 | 责任业务方 | 拒绝发布 / 降级为模拟 | 撤销发布 / 回滚写入 |
| 责任转移门禁 | 候选声称可承担真实责任 | 责任业务方 + 审计官 | 保留人工 / 降级为辅助 | 责任收回人工 |
| 交付决议门禁 | 审计结论产出后,交付前 | 责任业务方 | 拒绝交付 / 要求重试 / 保留人工 | 方案回退到上一阶段 |

## 高风险动作清单

### R1. 外部系统写入

| 项 | 内容 |
|---|---|
| 动作 | 向外部业务系统、数据库、API 或文件系统执行写入、更新、删除 |
| 触发条件 | 候选执行链路中任何产生持久化副作用的操作 |
| 审批主体 | 责任业务方(通过真实发布门禁) |
| 拒绝路径 | 拒绝写入,降级为沙箱模拟或只读分析 |
| 回滚路径 | 预定义撤销操作;无法撤销时降级为人工补救 |
| Trace 要求 | 记录写入目标、内容、时间、审批人、结果 |

### R2. 真实发布与部署

| 项 | 内容 |
|---|---|
| 动作 | 代码发布、模型部署、配置变更、服务上线等影响生产环境的操作 |
| 触发条件 | 软件研发类候选的发布阶段;运维类候选的修复执行阶段 |
| 审批主体 | 责任业务方(必须为人工,不得委派给候选 Agent) |
| 拒绝路径 | 拒绝发布,保留在沙箱;或降级为灰度/小范围 |
| 回滚路径 | 版本回退;服务回滚;灰度终止 |
| Trace 要求 | 发布版本、范围、审批人、灰度策略、回滚验证 |

### R3. 责任转移

| 项 | 内容 |
|---|---|
| 动作 | 候选声称可独立承担某项真实业务责任(如最终决策、客户回复、资金处置) |
| 触发条件 | 交付决议阶段,候选标记为"可部署" |
| 审批主体 | 责任业务方 + 审计官双重确认 |
| 拒绝路径 | 保留人工责任;降级为辅助决策;拒绝自动化 |
| 回滚路径 | 责任收回人工;候选降级 |
| Trace 要求 | 责任边界、转移条件、人工确认记录、责任收回路径 |

### R4. 密钥与凭证使用

| 项 | 内容 |
|---|---|
| 动作 | 调用需要鉴权的外部 API、数据库、云服务 |
| 触发条件 | 候选执行链路中任何需要凭证的操作 |
| 审批主体 | 基础设施层(密钥由基础设施持有,Agent 上下文不接触明文) |
| 拒绝路径 | 权限不足时降级为只读或沙箱;不得静默提升权限 |
| 回滚路径 | 凭证撤销;会话终止 |
| Trace 要求 | 调用目标、权限范围、时间、结果(不含凭证本身) |

### R5. 预算超限

| 项 | 内容 |
|---|---|
| 动作 | 候选执行消耗的 token、API 调用、工具调用、wall-clock 或人工投入接近或超过预算 |
| 触发条件 | 任一预算维度达到阈值(预警)或上限(硬停止) |
| 审批主体 | 责任业务方(预算变更门禁) |
| 拒绝路径 | 维持原预算并停止候选扩展;审计当前证据 |
| 回滚路径 | 不适用(预算只升不降需审批,且不得自动提升) |
| Trace 要求 | 各维度消耗记录、预警点、停止点、审计结论 |

### R6. 数据写入与污染

| 项 | 内容 |
|---|---|
| 动作 | 候选向 adaptation/validation/holdout 数据集写入或修改;跨数据集泄漏 |
| 触发条件 | 数据隔离边界被突破;holdout 被候选生成上下文接触 |
| 审批主体 | 审计官(独立判定) |
| 拒绝路径 | 判定该轮结果无效;重新建立数据隔离与试验 |
| 回滚路径 | 数据集回退到污染前快照;候选结果作废 |
| Trace 要求 | 数据版本、隔离边界、污染检测记录、无效化决定 |

### R7. 不可逆操作

| 项 | 内容 |
|---|---|
| 动作 | 任何无法通过预定义撤销路径回滚的操作(如删除原始数据、触发外部不可逆事件) |
| 触发条件 | 动作回滚路径分析显示无可撤销方案 |
| 审批主体 | 责任业务方 + 审计官;不可逆操作默认禁止,必须显式批准 |
| 拒绝路径 | 默认拒绝;降级为可逆模拟或人工执行 |
| 回滚路径 | 不适用(不可逆);必须事前证明必要性并保留完整证据 |
| Trace 要求 | 不可逆性证明、必要性论证、审批记录、执行证据 |

## 错误与降级矩阵

| 异常类型 | 自动处理 | 人工介入 | 记录 |
|---|---|---|---|
| Agent 不可用 | 阶段保持未完成 | 不由其他 Agent 静默冒充责任产物 | 失败 Trace |
| 结构化产物不合法 | 拒绝推进,返回字段错误 | 请求修正 | Schema 错误记录 |
| 能力或权限缺失 | 请求补充、缩小范围 | 或产生拒绝决议 | 缺口报告 |
| AgentTeams 通信异常 | 以项目档案状态为准 | 消息恢复后幂等重发 | 通信异常记录 |
| 评测预算耗尽 | 停止候选扩展 | 审计当前证据 | 预算消耗记录 |
| holdout 泄漏 | 该轮结果无效 | 重新建立试验 | 污染检测记录 |
| 高风险动作无批准 | 拒绝执行 | 保留 Trace | 门禁拒绝记录 |
| 循环失控 | 达到最大循环次数停止 | 按预定义降级路径 | 循环计数记录 |

## 与官方要求的映射

| 官方要求 | 本清单如何满足 |
|---|---|
| 高风险动作必须人工确认 | 6 类人工门禁 + 7 类高风险动作清单 |
| 审批记录 | 每个门禁记录审批主体、时间、结果 |
| 回滚路径 | 每个风险动作明确回滚方案(或证明不可逆并显式批准) |
| 审计边界 | 审计官独立判定;Trace 可追溯 |
| 失败证据保留 | 成功与失败证据同等保留;错误与降级矩阵覆盖 8 类异常 |
