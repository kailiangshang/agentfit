05 / 12 · 统一搜索空间

Agentless、单 Agent、多 Agent 与 Human 混合是同一搜索空间。

把“用几个 Agent”当成搜索变量：四类候选共享同一任务，多一个 Agent 都要证明边际价值，不预设多 Agent 更好。

C0 · AGENTLESS

固定流程基线

线索去重 → 规则筛选 → 配置/仓库检索 → 冻结验证。

强基线 · 低复杂度

输入稳定、变更模式已知时够用；跨文件不确定定位能力有限。

C1 · 单 AGENT

一个责任主体

定位 + 影响分析 + 修复 + 测试重试，统一上下文与决策。

少通信 · 长上下文

需检查权限集中、长上下文与自验偏差。

C2 · 多 AGENT

分责并独立验证

定位 / 修复 / 验证由不同主体承担；这里才可能生成 OpsPilot 式执行 Agent。

必须证明边际价值

新增通信、状态同步与错误归因成本。

C3 · HUMAN 混合

高风险交给人工

外部写入、真实发布、责任转移由 Human 批准并留痕。

Human 是正式能力

不是兜底文案，有触发、审批、回滚与 Trace。

Agent 数量是同一搜索空间里的变量，不是项目目标；OpsPilot 的 4 Worker + 1 Leader 只是 C2 的一种实例。
