内部架构：六角色协同——系统自身即样板

AgentFit 用自己倡导的纪律构建自己：多角色分权 + 确定性边界 + 消息因果链，覆盖从用户提交材料到交付的全链路

Agent 分工：六角色（3 个 LLM 认知体 + 3 个确定性官员 + 1 个人审）

角色职责实现
交互官 Steward材料操作化·澄清对话·解释呈现（用户唯一出口）LLM
编排者 Orchestrator任务分发·预算熔断·收敛·λ 调节确定性
归因师 Attributor失败样本→LossTrace（多实例并行扇出）LLM 槽位
架构师 Architect初始方案归纳·更新建议·级联检查LLM
验证官 Validator存在依赖·正则·回归裁决（COMMIT/ROLLBACK）纯代码
审计官 Auditor哈希链日志·预算监控·漂移检测纯代码

确定性边界（可审计的机制保证）

裁决 COMMIT 的验证官与审计官是纯确定性代码——同输入必同裁决，"禁止部分成功"机制级成立。
LLM 只进认知槽位（材料操作化/归因消歧/建议生成）：版本化 + 逐次计量 + 置信度 < 0.6 升级人审

消息因果链 + 任务分发

一切消息走总线（TaskMsg/ResultMsg），context_ref 串起同轮全部消息 → 任意决策可完整重建
路由表分发：INTAKE / BOOTSTRAP / ATTRIBUTE / PROPOSE / VALIDATE / REGRESSION / LOG
运行时禁止角色直呼（同层纪律）· 拓扑边声明式 · 上下文按引用传递

Skill 与工具集成：L3 Skill/排查链 调度 → L2 safe_* 封装 → L1 原子 → 可插拔执行环境（τ²-bench / 模拟器 / 生产影子模式）
异常分支与风险控制：升级人审 · 降级 · 拒绝自动化 · 回归回滚 · 预算熔断 · 漂移触发重训练——每条异常路径都有证据与日志
