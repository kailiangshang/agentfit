# Agent Identity 契约

## 设计原则

AgentFit 的四层骨架定义了 Agent 的身份不是"角色标签"，而是在架构中的位置和责任。

## L4 行为拓扑层的 Agent 定义

| 要素 | 定义 | 约束 |
|---|---|---|
| Agent 数量 | 由训练决定（Simple First：从 1 开始） | >5 需要证据支撑 |
| 协作模式 | Agent 间通信沿拓扑定义的边 | 不可隐式通信 |
| 行为序列 | 由 L3 知识驱动 | 不可凭空执行 |
| 人工介入 | 在拓扑中显式定义 | 不可隐式升级 |
| 升级路径 | 处理不了 → 转人工/降级/拒绝 | 必须有明确出口 |

## L3 知识层的五种知识身份

| 类型 | 身份 | 同层约束 |
|---|---|---|
| Skill | 可复用操作序列模板 | 禁止执行时调用另一个 Skill |
| 路由规则 | IF-THEN 条件调度 | 对 Skill/链的调度不算互引 |
| 排查链 | 有序步骤序列 | 禁止跳转到另一条链 |
| 决策阈值 | 数值化判断边界 | 少量，无强约束 |
| 经验记录 | 失败教训 | 禁止以另一条经验为依据 |

## L1 Solid 层的人工审核原子

人工审核是 L1 的标准原子，和 `query_database` 同级：

```
输入: question + context + options + domain
输出: decision + reason + conditions
L2 负责: 送谁审、怎么送、超时怎么办
L3 负责: 什么情况下触发
```
