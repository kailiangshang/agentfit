# GOAI Agent Infra 初赛要求矩阵

> 来源：[《新智基座》Agent Infra 参赛手册](../../reference/新智基座-参赛手册.pdf)
>
> 核验日期：2026-08-07
>
> 用途：约束 AgentFit 的证据研究、内部方案和初赛材料；不代表当前已经完成对应能力。

## 1. 初赛目标与提交物

来源：手册 §5.1–§5.2，印刷页 6–7。

| 提交物 | 要求 | AgentFit 必须准备的内部证据 |
|---|---|---|
| 作品简介 | 必交，500 字以内 | 项目名称、真实问题与场景、核心路线、差异化、开放复用价值、当前进展 |
| 方案 PPT/PDF | 必交 | 场景价值、系统架构、Agent 分工、任务拆解、协作流程、上下文、验证、异常、Skill、工具集成、评测、安全和开放计划 |
| 可执行 AgentTeams 代码包 | 初赛可选 | 如提交，必须具有运行入口、依赖、配置、样例输入输出和运行证据 |

初赛不强制要求可运行代码，但“当前进展”必须如实区分设计、模拟、原型、真实 AgentTeams 运行和真实业务评测。

## 2. 技术硬约束

来源：手册 §8、§9，印刷页 10–12；§11.1，印刷页 15–16。

| 约束 | 官方要求 | AgentFit 所需材料 |
|---|---|---|
| Agent 数量与职能 | 至少 3 个不同职能 Agent，身份清晰，共同完成端到端闭环 | 五个元 Agent 的 Identity 清单和独立责任产物 |
| AgentTeams | 必须作为协同设计基点 | 角色编排、任务拆解、上下文传递、协同执行和状态追踪的具体映射 |
| Agent Identity | 必须提交 | Name、Role、Capabilities、Inputs、Outputs、Dependencies、Decision Boundary、Trace |
| Skill | 必选 | 核心 Skill 清单、输入输出、调用条件、依赖、失败、安全、复用和协同关系 |
| 阿里云官方 Skills | 合理使用，按必要性而非数量评审 | 使用或不使用的证据化选择、替代方案和迁移成本 |
| MCP | 推荐可选 | 如不用，提供协议、鉴权、Schema、错误处理、审计、幂等、降级和迁移成本组成的等价契约 |
| 上下文能力 | 4 项至少实现 2 项 | Agent 记忆、知识库 RAG、共享状态、轨迹可观测中明确选择；不使用 RAG 时从其余 3 项至少实现 2 项，并论证上下文机制的有效性 |
| 可观测（如采用） | 推荐可选；一旦采用需说明设计 | 数据采集、语义规范、数据类型、后端存储与检索、应用效果；建议覆盖 Trace、Log、Metrics 中 1–2 类 |
| 工具链说明 | 对使用的开源项目或云产品均需说明 | 版本或兼容范围、调用方式，以及与 Agent、Skill、MCP、RAG 的关系 |
| 高风险动作 | 必须保留人工确认、审批、回滚和审计边界 | 风险动作清单、触发条件、审批记录、回滚路径和 Trace |
| 开放与合规 | 必须披露 | 开放范围、协议、依赖、商业 API、闭源模型、数据授权、脱敏、权限、关键版本、可复现方式、部署依赖和后续维护计划 |

## 3. 官方八步闭环

来源：手册 §8.3，印刷页 10–11。

| 步骤 | 官方要求 | AgentFit 证据对象 |
|---|---|---|
| 1. 任务输入 | 接收真实企业任务输入 | 原始材料与 `TaskSemanticSpec` |
| 2. 任务拆解 | 主控 Agent 或协同框架拆解任务 | Task Envelope、阶段状态和责任 Agent |
| 3. 上下文传递 | 传递历史、工具结果和中间结论 | Project Dossier、消息和 Artifact 引用 |
| 4. 工具调用 | 调用 Skill、MCP、系统、知识库或接口 | `CapabilitySemanticSpec`、调用契约和权限 |
| 5. 结果验证 | 验证执行或分析结果 | Trial、留出评测和人工复核 |
| 6. 执行证据沉淀 | 保存日志、Trace、Metrics、报告或截图 | `ExecutionTrace` 与 Evidence Bundle |
| 7. 审批与回滚 | 高风险动作可确认、审批、回滚和审计 | Approval Record、Rollback Record |
| 8. 经验沉淀 | 把结果和复盘转为可复用能力 | BatchAsset/ScenarioAsset(场景内持续学习,经回归池验证) |

## 4. 评分矩阵

来源：手册 §12.1–§12.2，印刷页 16–17。

| 评审维度 | 权重 | 直接需要的内部证据 |
|---|---:|---|
| 场景价值与行业可复制性 | 25% | 真实输入输出、人工或现有基线、价值指标、适用边界、跨行业或跨流程迁移依据 |
| 多 Agent 协同与自主闭环能力 | 25% | Identity、职责、拆解、结构化上下文、异常冲突、多方案选择、审批回滚和审计 |
| Skill 工程体系与生态复用 | 25% | Skill 契约、跨 Agent/场景复用、版本、发布、回滚、质量评估和 AgentTeams/官方 Skill 关系 |
| 工程落地、运行验证与安全可审计 | 20% | 可运行或等价材料、配置依赖、Trace/Log/Metrics、MCP/RAG/可观测链路、数据权限密钥和降级 |
| 开放 / 开源贡献 | 5% | 可复用成果、接口契约、文档、示例、协议和第三方依赖 |

评审不按推荐工具或云产品的使用数量评分，而是检查必要性、接口契约、可替换性、权限边界、闭环证据和迁移成本。

## 6. 阶段边界

初赛材料可以描述技术方案和后续计划，但必须明确当前完成度。进入复赛后，可执行 AgentTeams 代码包、可运行 Demo 或视频、技术文档和验证材料成为必交内容。初赛对这些内容的承诺必须能够在复赛期限内落实。
