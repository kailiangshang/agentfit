# GOAI Agent Infra 初赛红线与声明检查表

> 来源：[《新智基座》Agent Infra 参赛手册](../../reference/新智基座-参赛手册.pdf) §11、§13
>
> 核验日期：2026-08-07

该清单用于审查初赛简介、PPT/PDF和任何可选证据包。每项必须能够回答“满足”“不适用并说明原因”或“尚未完成且已在材料中声明”。

## 1. 可验证性

- 是否至少提供 PoC、实验、仿真、日志、Trace、视频、平台成绩或其他等价证据之一；
- 是否避免把概念图、设计图或营销文字称为运行证据；
- 是否为每个指标记录来源、样本、计算方式和适用范围；
- 是否保留失败、降级和拒绝自动化案例，而非只展示成功样例；
- 是否能够从提交材料反向定位到内部 Evidence Registry、Trace 或评测报告。

## 2. AgentTeams 真实性

- 是否具体说明 AgentFit 角色、任务、上下文、状态和 Trace 如何映射到 AgentTeams；
- 是否区分“以 AgentTeams 为设计基点”“已运行 AgentTeams 原型”和“已完成真实业务验证”；
- 是否避免把本地同步模拟器描述为 AgentTeams 运行；
- 是否披露当前使用的 AgentTeams 版本、已验证能力和未验证边界；
- 是否避免仅出现 AgentTeams 名称而没有协同设计。

## 3. 团队贡献与既有基础

- 是否披露 AgentFit 在比赛前已有的代码、文档和 AgentTeams fork 基础；
- 是否说明本团队新增的方法论、证据、实现和实验；
- 是否避免使用未披露的外部代码、报告或他人成果；
- 是否保留第三方内容的作者、URL、协议和版本；
- 是否避免任何伪造 Star、Fork、Issue、PR、实验或平台成绩的行为。

## 4. 数据、模型与依赖

- 是否记录每个数据集或业务材料的来源、授权、脱敏和再分发条件；
- 是否披露商业 API 的调用环节、费用、权限、替代方案和锁定风险；
- 是否披露闭源模型的使用范围、原因、替代方案和可复现性影响；
- 是否记录开源依赖、许可证、版本和修改范围；
- 是否说明每个开源项目或云产品的兼容范围、调用方式，以及与 Agent、Skill、MCP、RAG 的关系；
- 是否记录 MCP、工具、外部系统和数据库的权限边界与真实接入状态。
- 是否说明可复现方式、部署依赖和后续维护计划。

## 5. 可观测与上下文机制

- 采用可观测时，是否说明数据采集、语义规范、数据类型、后端存储与检索以及应用效果；
- 是否至少明确计划覆盖 Trace、Log、Metrics 中的 1–2 类数据；
- 是否说明评测结果如何回流 Dataset、Prompt、Skill、RAG、MCP、模型或其他非 LLM 参数；
- 不采用 RAG 时，是否从 Agent 记忆、共享状态、轨迹可观测中至少实现 2 项；
- 是否用评测证据论证所选上下文机制有效，而不仅是列出组件名称。

## 6. 高风险动作

- 是否列出涉及外部写入、部署、权限提升、真实用户或敏感数据的动作；
- 是否为每个高风险动作定义人工确认和审批主体；
- 是否定义失败、拒绝、超时和撤销后的降级或回滚路径；
- 是否在 Trace 中记录动作、权限、审批人、输入、结果和回滚；
- 是否明确不能自动化或责任不能安全转移的任务边界。

## 7. 内外材料一致性

- 500 字简介、PPT、演示脚本和代码仓库是否使用相同项目定义；
- Agent 数量、Identity、Skill、工具、数据、指标和当前进展是否一致；
- 比赛材料中的每个完成态声明是否存在内部证据指针；
- 未来计划是否明确标记为计划，而非当前能力；
- 复赛承诺是否具有清晰范围、依赖和可执行路径。

## 8. 官方严重扣分项

手册 §13 明确列出的风险包括：作弊与私下共享代码、只有概念或营销材料而无可验证证据、核心 Demo 无法复现、阶段承诺严重不一致、未披露既有项目基础、抄袭或伪造社区与实验数据，以及数据、License、商业 API、闭源模型或安全边界披露不实。提交前必须逐项复核。
